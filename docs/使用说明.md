# Nexus Mods 增强 1.5.0 — 按 mod 归档下载

一次下载 = 一个 `<Mod名>/` 文件夹，压缩包和预览图都在里面。图片也可以单独下，不再跟着压缩包一起请求。

## 一、装哪个文件

```
nexus-mods-plus.user.js                          ← 1.5.0，装这个
archive/nexus-mods-plus-1.3.3.orig.user.js       ← 原版备份，出问题直接换回来
```

ScriptCat / Tampermonkey 里删掉旧版，再装新版（同名脚本不要同时启用两个，会双份注入）。

## 二、第一次使用：必须选一次保存目录

打开任意 mod 详情页 → 右下角浮坞「⬇ 下载」→ 面板里点：

```
① 选择保存目录（建文件夹必选）
```

浏览器会弹目录选择器，选一个根目录（可以是 NAS 网络盘）。选完之后：

- 每次下载自动在该目录下建 `<Mod名>/`
- 压缩包、图片都写进去
- **这个授权只需一次**，之后一直复用（浏览器重启后可能提示重新授权，点一下按钮即可）

### 为什么必须选目录

脚本有两条落盘通道，只有第一条能保证建文件夹：

| 通道 | 建子目录 | 说明 |
|---|---|---|
| **文件系统通道**（选目录后） | **一定建** | 脚本自己 `getDirectoryHandle(名字,{create:true})` 建目录、自己写文件，不经过管理器、不经过浏览器下载设置 |
| GM_download 通道（没选目录时） | 不保证 | 能不能建取决于脚本管理器是否把 `name` 原样传给 `chrome.downloads.filename`，实测有环境不生效，文件会直接落在下载根目录 |

所以：**不选目录 = 可能没有文件夹**。面板按钮文案会一直提示「建文件夹必选」。

## 三、图片：独立按钮

| 控件 | 行为 |
|---|---|
| `下载图片` 按钮 | 单独把当前 mod 的预览图（**原图**，保留原始文件名）下到 `<Mod名>/`，不碰压缩包 |

默认不勾的原因：图库动辄十几张，每次下 mod 都顺带请求一遍既费流量也拖慢队列。

产物示例：

```
<你选的目录>/
└── Snowbreak_ Containment Zone/                     ← 游戏名（面包屑第二级）
    └── Vidya_Agave(default)_a little naughty/       ← Mod 标题
        ├── Vidya_Agave-1064-1-0-1760599327.zip
        ├── 868-1760599327-512078410.png
        └── 868-1760599338-1231626948.png
```

同一游戏的 mod 会聚在同一个游戏目录下；拿不到游戏名时只留 Mod 标题一层。

合集页批量下载同样生效：每个 mod 各自一个文件夹，扁平结构，不套合集名。

## 三之二、关于授权（刷新页面后为什么会再问一次）

| 项 | 行为 |
|---|---|
| 记住你选了哪个文件夹 | 会。目录 handle 存在浏览器 IndexedDB 里，刷新、重开浏览器都还在 |
| 免掉「允许访问」确认 | **不会**。普通网页的目录访问权限在页面刷新后退回待确认，需要点一次「允许」 |
| 需要重新选文件夹吗 | 不需要。刷新后直接点下载，弹的是权限确认（不是目录选择器），点允许即可 |

如果面板显示「保存目录记录丢失」，说明浏览器清了本站站点数据，需要重新选一次目录。

## 三之三、断点续传

下载中断（网络抖动、切换后台、刷新页面）后**不用从头重下**，点同一个文件的「一键下载」会从已下载位置继续。

| 项 | 行为 |
|---|---|
| 进度保存位置 | 浏览器私有存储（OPFS），不占用你选的保存目录 |
| 保存时机 | 每收到一块数据就落盘，最多丢最后一块 |
| 刷新页面后 | 断点仍在，重新点下载即可接上 |
| 文件已更新 | 自动作废旧断点，从头下载，不会拼接出错 |
| 下载完成后 | 自动复制到 `<游戏名>/<Mod名>/`，再清理临时文件 |
| 面板提示 | 续传时状态行显示「从断点 xx MB 继续下载」 |

适用条件：需要通过「选择保存目录」走文件系统通道（浏览器下载通道由浏览器自己管续传）。

## 三之四、脚本设置面板

点右下角浮坞的「⚙ 配置」（或脚本菜单「脚本设置」）打开，分三区：

| 分区 | 可设项 |
|---|---|
| 下载 | 保存目录、按 mod 建文件夹、每 mod 最多图片数、合集下载间隔、跳过下载等待页 |
| 界面 | 每页条数、界面中文化、模组语言徽章 |
| AI（翻译 / 分析） | API 地址、API Key、模型；带「测试 AI」连通性检查 |

保存后下载设置**立即生效**；每页条数、中文化、语言徽章影响列表渲染，会提示刷新页面后生效。

底部按钮固定在面板底部，内容再长也不用滚到底才能保存。

## 三之五、切到后台会暂停，不会失败

浏览器把后台页面冻结后，网页自己发起的下载会断掉。脚本处理方式是主动暂停：

| 情况 | 面板显示 | 数据 |
|---|---|---|
| 切到后台 | 「已暂停：浏览器切到后台，回到前台会自动继续」 | 已下载部分完整保留 |
| 回到前台 | 「已回到前台，继续下载」 | 自动从断点接着下，不用重新点 |

所以慢速下载时不用一直盯着，切走再回来会自己接上。

注意两点：

- 这个行为只针对**文件系统通道**（选了保存目录）。没选目录时走浏览器原生下载，由浏览器进程管理，切后台会继续下。
- 如果浏览器把页面彻底丢弃（内存不足时会发生），自动恢复就没了，但断点还在，重新点下载会接着下。

## 三之六、已下载标记

Nexus 文件页会对下载过的文件显示 `Downloaded` 日期。脚本把同一信息同步到下载面板里：文件行后面出现绿色「已下载」徽章。

| 项 | 说明 |
|---|---|
| 数据来源 | 页面上的 `li.stat-downloaded` 或 `downloaded` 图标，任一存在即算下载过 |
| 为什么用它 | 这是账号级数据，能覆盖你在官网、Vortex 或浏览器里下载过的记录，比本地记录全 |
| 匹配方式 | 文件 ID 优先；页面文件行没有 ID 时退回文件名比对（折叠空格、忽略大小写） |
| 数据来源一 | 页面上的已下载标记——**只有文件页（`tab=files`）有** |
| 数据来源二 | 本机下载记录（脚本自己记的），**任意页面都有** |
| 什么时候更新 | 打开面板、点「刷新文件列表」、或下载完成后立刻更新 |

### 为什么文件级状态在描述页拿不到

N 网的接口只提供 **mod 级**的个人下载状态（`viewerDownloaded`，任意页面可查），**文件级没有对应字段**。所以：

- **文件页**：页面 DOM 有每个文件的已下载标记，最准
- **其他页面**：只能靠本机记录（本脚本下载过的），或者给一句 mod 级的总体提示

如果你在官网或 Vortex 里下载过、但没用本脚本，描述页就只会显示「你下载过这个 mod」而无法指出是哪个文件——这是数据源的上限，不是标记没生效。

## 三之七、下载进度

每个文件行自带一条进度条，**同时下载多个文件时各显示各的，不会互相覆盖**。

| 位置 | 显示内容 |
|---|---|
| 文件行内 | 细进度条 + `已下载 / 总大小 · 百分比` |
| 面板状态行 | 文本进度条 `[██████░░░░] 62% · 7.9MB / 12.8MB` |
| 按钮 | 下载中显示「下载中…」，完成恢复「一键下载」 |

完成后进度条收起，该行出现绿色「已下载」徽章。

## 四、验证功能是否正常

脚本菜单（管理器里点脚本名 → 命令列表）：

```
归档下载：自测能否自动建文件夹
```

- 没选目录时它会直接提示你先去选（不会用 GM_download 通道测出假结果）
- 选好目录后点它，会往 `NME自测/self-test.png` 写一张 211KB 的测试图
- 看到 `NME自测/self-test.png` → 通道正常
- 提示「浏览器不支持 File System Access」→ 换 Chrome / Edge

## 五、已知边界

| 情况 | 行为 |
|---|---|
| 合集批量下载 | 图片只下**封面 1 张**（合集页没有每个 mod 的图库 DOM，不为每张图多打一次详情页） |
| 文件系统通道下的大文件 | 边下边写、面板显示进度；按钮会一直禁用直到写完（几百 MB 需要等） |
| mod 标题含 `\ / : * ? " < > \|` | 替换成 `_`，否则建目录失败 |
| mod 标题超长 | 截断到 80 字符；首尾的点与空格去掉（Windows 不允许结尾点） |
| 文件名没有扩展名 | 按「声明名 → 直链末段 → `<Mod名>-<版本>.zip`」三级兜底 |
| 同名文件已存在 | 不再覆盖：自动改名为 `xxx (1).zip`，原文件保留 |
| 文件名 | 文件系统通道以本次下载响应里的真名为准，面板显示的名字就是实际落盘的名字；拿不到真名时两边都用同一兜底名，不会再出现同一次下载留下两个文件 |
| 单张图片失败 | 跳过并记日志，不影响压缩包 |
| 关掉「按 mod 建文件夹」 | 回到 1.3.3 行为：单文件直接落下载根目录 |
| 浏览器不支持 File System Access | 按钮隐藏，自动退回 GM_download 通道 |

## 六、技术要点（维护者看）

**为什么 `a[download]` 建不出目录**：`download` 属性只是「建议文件名」，不含路径，Chrome 会把其中的 `/` 换成 `_`。

**为什么 GM_download 通道不可靠**：它把 `name` 交给 `chrome.downloads.download({filename})`，Chrome 确实支持 `filename` 含子目录（官方文档 *"possibly containing subdirectories"*），ScriptCat 的 `cleanFileName()` 也保留了 `/`。但这条链路要经过脚本管理器，不同版本/实现可能把 `name` 当纯文件名处理，实测有环境不生效。

**为什么文件系统通道一定行**：`showDirectoryPicker()` 拿到根目录 handle 后，`getDirectoryHandle(name,{create:true})` 由脚本直接建目录，`createWritable()` 直接写字节，全程不经过管理器与浏览器下载设置。

**几个实现细节**：

- `showDirectoryPicker` 必须在用户点击事件里调用（浏览器要求用户手势），所以只能放在按钮回调
- 目录 handle 存 IndexedDB（`FileSystemDirectoryHandle` 支持结构化克隆），刷新页面后复用
- 权限查询用 `queryPermission`，不用 `requestPermission`（后者必须手势，异步链里会失效）；面板按钮会提示重新授权
- 数据获取先走 `fetch`（图片 CDN 实测 `access-control-allow-origin: *`），跨域被拒时退回 `GM_xmlhttpRequest` 取 blob
- 进度每 500ms 才刷一次面板，避免大文件把 DOM 刷爆
- 油猴沙箱里 `window` 可能是代理，`showDirectoryPicker` 优先从 `unsafeWindow` 取
